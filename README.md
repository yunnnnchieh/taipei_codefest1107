# 台北車站立體導覽

網頁直接讀取你提供的 `station.json`，並用四張樓層 PNG 畫出立體示意圖。專案可在一般瀏覽器執行，不需要安裝前端套件。

## 啟動

1. 解壓縮 ZIP。
2. 在 `taipei-station-3d` 目錄開啟終端機，執行 `python3 -m http.server 8000`。
3. 打開 [本機導覽](http://localhost:8000/)。網頁需要透過 HTTP 讀取 JSON 和 JavaScript 模組。
4. 也可以將整個資料夾放在支援靜態檔案的網站空間，用 iPhone Safari 開啟該網址。

## 試走

- 起點選 B3「3月台：南港展覽館方向」，目的地選 G「M8地面出口：公園路」。
- 拖曳地圖可改變角度。可切換單一樓層、俯視或縮放，也可以開啟圖上選點，點選地標圓點。
- 逐段查看下一個地標。到達後按「已到下一個地標」，紅點會移到該地標。
- 橘色虛線是推定路段。啟用「排除推定路段」後，示例路線會顯示無連通路線。「避開樓梯與手扶梯」依資料過濾路段，無障礙通行條件仍需現場確認。

## AR 步伐引導

1. 在 iPhone Safari 用 HTTPS 網址開啟，選起點與目的地，按「開啟 AR 地面引導」並允許相機。
2. 面向第一段通道，按一次「開始步伐引導」。允許動作與方向權限後，步伐會推動紅點，朝向用於旋轉引導帶與小地圖。後續路段沿用初次對準；方向漂移時可以按「重設朝向」。
3. 有轉彎的步行段會立即顯示金色圓弧，位置經過畫面調整，便於直行時先看見。走到實際轉角或地標時按「到了」，再切換至下一段。收到步伐訊號以前，可按「補一步」試看紅點。
4. 小地圖固定比例，只顯示當層的附近區域；確認抵達跨樓層設施的另一端後才換層。

每步暫估 0.65 公尺，沿用舊版以出口估得的 B1 平面比例並暫套其他樓層。步數、剩餘距離和圓弧時機都需現場校驗。相機只用於即時顯示，沒有地面錨定或照片辨識。

## 城市通微服務樣式

依你提供的《城市通微服務開發指南》第 4 節配置青藍主色、金色輔色與灰階。參考官方 [色票](https://github.com/taipei-doit/TownPass/blob/main/lib/util/tp_colors.dart) 與[文字樣式](https://github.com/taipei-doit/TownPass/blob/main/lib/util/tp_text_styles.dart)。中文優先使用系統 PingFang TC，英數使用本地 Roboto。字型來源為 Google Fonts，授權見 `assets/roboto-OFL.txt`。

互動元件以 48 CSS px 為觸控目標。已於一般瀏覽器以 390 px 手機寬度與 320 px、200% 文字大小驗證。這是可由瀏覽器開啟的網頁樣式版本，城市通 App 內的 WebView 相機與感測權限仍需實機整合測試。

## 資料與架構

- `index.html`、`style.css` 負責介面。
- `app.mjs` 讀取 `station.json` 並管理選點、路線條件和逐段進度。
- `routes.mjs` 以可通行的有向邊找路，依序比較過閘次數、跨越的樓層數和路段數。此優先順序沿用原始路網的 Python 範例。
- `ar-camera.mjs` 管理相機、朝向校準、步伐和 AR 逐段引導。`ar-route.mjs` 從路網折線算通道方向和轉彎，`ground-guide.mjs` 畫動態地面引導帶。
- `scene.mjs` 將平面座標、樓層和跨層連線投影到可旋轉的畫布。G 層圖標借用地下連接點的平面位置，樓層間距為示意值。
- 原樣保留你提供的 `station.json`、`station.schema.json` 與 `assets/B1.png` 到 `assets/B4.png`。來源詳見 JSON 的 `sources`，包含《051 (1).pdf》與[台北捷運台北車站頁](https://web.metro.taipei/pages2026/WebStation/051)。
- 本版使用手動定位。樓層位置與跨層連線依原始資料呈現，距離、時間和實際樓高尚未標定。資料測試可驗證路網連通性，現場走法仍以站內標示為準。
